# Мобильный Paywall для детской игры (Nuxt 4 + NuxtHub)

Интерактивный экран оплаты (Paywall), разработанный специально для отображения во встроенном мобильном Webview игрового приложения. Проект объединяет современный фронтенд-интерфейс и изолированную серверную часть в рамках единого fullstack-репозитория.

---

## 🚀 Как запустить проект локально

### 1. Подготовка окружения
Убедитесь, что у вас установлена стабильная версия Node.js (рекомендуется **Node 22 LTS** или **Node 24 LTS**).

### 2. Установка зависимостей
Установите все необходимые пакеты, включая компилятор TypeScript для сборщика Rolldown:
```bash
npm install
```

### 3. Генерация виртуальных типов Nuxt
Для того чтобы TypeScript корректно распознал автоимпорты и встроенные глобальные методы базы данных, сгенерируйте локальные типы среды:
```bash
npx nuxt prepare
```

### 4. Запуск сервера разработки
Запустите локальное edge-окружение:
```bash
npm run dev
```
После старта приложение будет доступно по адресу: `http://localhost:3000`

## 📁 Архитектура: где что находится

Проект строго следует современной архитектуре **Nuxt 4**:

*   **Фронтенд (`./app/app.vue`)** — единая точка входа клиентского приложения. Здесь реализована mobile-first верстка экрана (целевая ширина 360–430px) с использованием шрифта `Aldrich`.
    *   Данные о тарифах загружаются динамически через асинхронный хук `useFetch`.
    *   Реализована обработка состояний загрузки (`pending` со спиннером) и сетевых ошибок (`error` с кнопкой повтора).
    *   По клику на CTA-кнопку `UPGRADE TO PRO` отправляется безопасный `POST`-запрос на бэкенд.
*   **Серверные роуты (`./server/api/`)** — бэкенд-логика, изолированная на движке Nitro и исполняемая строго на сервере:
    *   `GET /server/api/offers.get.ts` — возвращает актуальный массив тарифов (заголовок, цены, периоды и описание) с имитацией задержки сети.
    *   `POST /server/api/purchase.post.ts` — принимает выбранный `offerId` и `userId` устройства, валидирует входящие параметры и записывает транзакцию в БД.
*   **База данных (`./server/database/schema.sql`)** — SQL-скрипт инициализации структуры таблиц.

## 🛠 Выбор платформы деплоя и базы данных

*   **Платформа деплоя:** **Cloudflare Pages** (посредством платформы **NuxtHub**). Данный стек выбран из-за бесшовной нативной поддержки архитектуры Nuxt 4, мгновенной компиляции серверных роутов в легковесные Edge-функции (Cloudflare Workers) и отличного бесплатного лимита без ограничений по времени.
*   **База данных:** **Cloudflare D1 (SQLite)** через утилиту `@nuxthub/core`. Интеграция метода `hubDB()` позволила организовать полноценное persistent-хранилище данных «из коробки» без подключения сторонних сервисов (вроде Supabase или Neon), ручного прописывания секретных токенов в `.env` и разворачивания тяжелых ORM. В базу записываются: `offer_id`, условный `user_id` устройства и точная дата транзакции `created_at`.

## 🤖 Использованные AI-инструменты и ручная проверка

*   **AI-инструменты:** ИИ-ассистент применялся для проектирования и адаптации стилей фонового радиального градиента из Figma, выстраивания точных визуальных отступов (`margin-bottom: 100px`) между логическими блоками пейволла для достижения 99% соответствия Pixel Perfect, а также генерации базовых скелетов обработчиков роутов Nitro.
*   **Проверено вручную:** Самостоятельно локализована и исправлена синтаксическая ошибка типизации входящих интерфейсов (`interface`), приводившая к сбою встроенного TS-стриппера в среде Node 22. Также вручную устранены ошибки экранирования спецсимволов (`\$`) в шаблонах Vite и скорректировано использование обновленного метода `hubDB()` вместо устаревшего `hubDatabase()`.

3.  **Анимации и стейт успеха:** Сверстал бы полноценный красивый экран успешной транзакции (Success State) с анимацией конфетти с помощью `canvas-confetti` для улучшения UX.
